# Changelog

Every release of `@design-library/core` and `@design-library/templates` (they share one version). Newest first.

**Versions:** `MAJOR.MINOR.PATCH`. While the major is `0`, a **minor** release may break a public contract (a prop, a block type, a token name, a content schema version, an export) and says how to upgrade under "Breaking"; a **patch** never breaks one. From `1.0.0`, only a major release breaks.

**Contracts that carry their own version:** the content schemas (`schemas/*.json`, `$id …/1`), the colour config (`colour-config/2`, `CONTRACT` in `@design-library/core/colour`), and each template's `content.schema.json`. A release that changes one names it here with the migration.

## Unreleased

- **Added (IP20):** `Grid` `ratio` for two uneven columns: `'2:1'`, `'3:2'`, `'1:2'`, `'2:3'`, and `'aside'` (a heading beside its content, the start column at the new theme setting `--c-grid-aside`, default 16 rem). Children alternate start and end; the pair stacks in source order when the narrower share would fall below `size.column-min`, so nothing scrolls sideways at 320 px. Without `ratio` nothing changes. **Adopt:** replace DesignUp's hand splits (`designup.css` `526fr 565fr`, `553fr 530fr`, `665fr 520fr` and the hero words column) with `<Grid ratio="…">`, and the sponsors layout's intro beside the wall (`sponsors-layout.css`, `--t-designup-sponsors-layout-intro-width`) with `<Grid ratio="aside">` plus `applySettings({ '--c-grid-aside': … })`.
- **Added (IP21, opt-in):** the contrast guard. `Brand` takes `contrast` (`'keep'` default, `'guard'`). With `'guard'`, `applyBrand` and `brandCss` measure links (4.5:1 on the page and raised surfaces), the label on the accent fill and its hover and pressed fills (4.5:1) and the focus ring (3:1) in light and dark, and move only the failing roles: links and the ring to the nearest passing step, the label to the ink that reads best (dark on yellow), then the fill. Without it the output is unchanged. `brandVars` now also returns `warnings` naming each failing pair (with or without the guard), and the new `brandContrast(brand)` returns every pair measured (type `BrandPair`). Measured on the four bright seeds pinned at 500: `#fd6f02` link 4.1 → 6.3:1, label 2.8 → 6.6:1, ring 2.7 → 4.1:1; `#ffd400` link 2.1 → 6.4:1, label 1.4 → 13.1:1; `#7ed957` link 2.5 → 7.4:1, label 1.7 → 10.7:1; `#00b3ff` link 3.4 → 5.5:1, label 2.3 → 7.9:1 (light; dark already passes). **Adopt:** add `contrast: 'guard'` to the brand in DesignUp's `look.ts` (orange pinned at 500); its link reads 6.3:1 and button labels turn dark on the orange, so any hand-darkened link colour or label override can go.
- **Added (IP22):** accent word roles `color.text-accent` (4.5:1, body text and small headings) and `color.text-accent-display` (3:1, heading 2 and larger, statements); `Text` `tone="accent"`, `Heading` `tone="accent"`, and `Text` `variant="inherit"` for a span that keeps the size, face and weight around it (`<Text as="span" variant="inherit" tone="accent">`). An accent span inside large text reads the display role on its own. The contrast guard (IP21) also measures and moves both roles. Nothing changes without the tone. **Adopt:** DesignUp's `accentPhrase` and `accentTail` helpers in its views (the orange words in headings and small text) become `<Text as="span" variant="inherit" tone="accent">`; with `contrast: 'guard'` the orange small text stops failing on paper.
- **Added (DP1):** rich inline text in content. `blocks.schema.json` gains `$defs.richText` (a string, or a list of strings and runs `{ "text", "mark" }` marked `emphasis`, `strong`, `accent`, `code`, `link` with `href`, and `{ "mark": "break" }`) and `$defs.richHeading` (emphasis, accent and break only). First fields: `hero` and `cta` `title` (heading marks) and `lead`, and `prose` heading and text items; a plain string stays valid everywhere, and a wrong mark fails the content check at its JSON path. `@design-library/core/render` exports `richText(value)`, `plainText(value)` and `<RichText value>`, and the types `RichText` and `RichRun`; `Hero` `title` and `lead` now take any node. **Adopt:** DesignUp's `accentPhrase`/`accentTail` calls in its views (19, with the split hard-coded) become content: `"title": ["Design ", { "text": "up", "mark": "accent" }]` drawn with `richText(...)`.

## 0.2.0-beta.2 (2026-11-10): first improvements from a real site

The first round of improvements from the DesignUp beta report: install guidance, theme settings, link decoration, a base (canvas) colour, tracking, link buttons, Section tone, lead and statement text, wider picture ratios with a focal point, live and form-mode fields, the project check and `Hero` media. **Nothing breaks:** every line is an addition, an opt-in or a default kept, except one default change under reduced motion only (`viewTransition`). How to adopt each: `UPGRADE.md`.

Every line ends with how to adopt it.

- **Changed (default, under reduced motion only; ID1, Q105.3):** `viewTransition()` now swaps the view in the same frame when motion is reduced (system setting or `data-motion="reduce"`), instead of cross-fading. Nothing changes when motion isn't reduced. **Opt-out:** pass `reducedMotion: 'fade'` to keep the earlier fade. Also exported: `prefersReducedMotion()` and the `ViewTransitionOptions` type. **Adopt:** remove your own reduced-motion test around `viewTransition` (DesignUp `App.tsx`) and call it directly.
- **Added (ID4):** theme settings, a published allow-list of the component tokens a project may set (`tokens/settings.json`; each component's contract in `agent/components/{Name}.json` lists its `settings` with defaults). First: SiteLayout's frame, `--c-site-layout-width`, `-reading`, `-margin`, `-gap`, `-padding-block` and the new optional `-padding-start` (space above the first band only). Set them with `applySettings(settings)` or `settingsCss(settings, selector)` from `@design-library/core/theme`, which refuse any name off the list; `themeSettings` and `settingsErrors` are exported too. Setting the same properties in your own stylesheet keeps working. **Adopt:** move DesignUp's four `--c-site-layout-*` overrides (`web/src/templates/designup/tokens/tokens.css`) into one `applySettings({...})` call in `look.ts`; nothing changes on screen.
- **Added:** `SiteLayout` `opening` (`'spaced'` default, `'flush'`): the first band meets the header. Also a content setting, `"opening": "flush"` in `settings.SiteLayout`. **Adopt:** where DesignUp set `--c-site-layout-padding-block` to pull the opening up under the header, use `opening="flush"` (or `'--c-site-layout-padding-start': '0px'`) and keep the bottom space.
- **Added:** link decoration tokens `link.decoration` (rest, `underline` default) and `link.decoration-hover` (hover and keyboard focus, `underline`), read by `Link` and Pagination's neighbour titles; both on the theme-settings allow-list. With the rest line off, the line comes back on hover and focus, and the link colour owes 3:1 against the text around it. Default output is unchanged. **Adopt:** replace DesignUp's `:any-link * { text-decoration: none; }` (`parts/designup.css:13`, which also reached inside core parts) with `applySettings({ '--link-decoration': 'none' })`.
- **Added:** `applyBrand` takes `base` (`temperature` neutral, warm or cool; an optional `tint`; `pins` by step) and writes the base ramp and its ink layers; without `base` nothing changes. New type `BaseColours`. **Adopt:** replace DesignUp's hand call to `generate()` and the `--p-base-*` loop in `look.ts` with `applyBrand({ ...brand, base: paper })`.
- **Added:** tracking roles `tracking.wide` (0.05em) and `tracking.wider` (0.1em) for short labels in capitals or small sizes. **Adopt:** point DesignUp's `--t-designup-label-tracking` and `-list-tracking` at `var(--tracking-wide)` or `var(--tracking-wider)` instead of raw em values.
- **Added:** `Button` `href`: a link (`a[href]`) with the button's look, sizes, icon and focus ring, for a destination that is the main call to action; `onClick` receives the click event (a router may `preventDefault`), `unavailable` keeps it focusable and stops it going. Buttons without `href` are unchanged. **Adopt:** DesignUp's `HeaderEnd` button that sets `location.hash` becomes `<Button href="#/…" … />`.
- **Added:** `onPointerEnter`, `onPointerLeave`, `onFocus` and `onBlur` on `Link` and `Button` (Button runs them beside its own hint). **Adopt:** drop the event delegation DesignUp's index list uses to preview the pointed row, and pass the handlers on each `Link`.
- **Added:** `Section` `tone` (`sunken`, `raised`, `tint`, from the elevation ladder; new tokens `c.section.tone-*`) and `bleed` (the fill runs to the window's edges as a band). Without `tone` nothing changes. **Adopt:** replace DesignUp's custom tinted-band part with `<Section tone="…" bleed>`.
- **Added (ID9):** `Text` variants `lead` (body-scale prose a step up, 20 px) and `statement` (one display-scale sentence, 48 px, between heading 1 and display), with type tokens `type.lead.*` and `type.statement.*`. **Adopt:** DesignUp's facts set as a heading become `<Text variant="statement">`; lead paragraphs drawn in custom parts become `<Text variant="lead">`.
- **Added:** `Image` ratios `ultrawide` (21:9) and `classic` (4:3), also on `Card`; `Image` `focal` (`{ x, y }` from 0 to 1, the same field as a picture entry's `focal`) keeps a point in view when the frame crops, also on `Hero`'s `picture`. **Adopt:** DesignUp's collage frames and `PhotoFrame` crops use `ratio` and `focal` on core `Image` instead of native `img` with `object-position`.
- **Story, no new prop (ID10):** a `Card`'s status is a `Badge` in `meta` beside the date ("Status in the meta line" on the Card page). **Adopt:** DesignUp's "Ended" and "Coming up" eyebrow text becomes `meta={<Cluster gap="pair"><Badge>Ended</Badge>21 Jan</Cluster>}`.
- **Added:** `TextField` `onChange` (every keystroke), `name`, `mode` (`'commit'` default, `'form'`) and `words` (its saved announcement, Retry, Revert, Clear, Show, Hide, a chip's remove button, a code's length; English defaults unchanged). In `form` mode nothing saves on blur or Enter, no state or "Saved" shows on the field, and Enter submits the form; `onCommit` is now optional (needed in commit mode). `Select` and `NumberField` take `mode="form"` too, and `Select` takes `savedText`. Commit mode is unchanged. **Adopt:** DesignUp's enquiry fields take `mode="form"` with `onChange` (no more "Saved" per field); its talk search takes `onChange` so the list narrows as people type.
- **Docs (IP1):** the install step states what each release is checked on (npm 9.6.7, 10.8.2 and 11, in the guide's order and again from the lockfile) and what to do if npm stops with `edgesOut` (clear `node_modules`, `package-lock.json` and the cache; then npm 11; never `--force`). The 0.2.0-beta.1 files install cleanly on all three. **Adopt:** nothing to change; DesignUp's "use npm 11" note may stay.
- **Docs (IP2):** "Rules agents miss" no longer names a `Grid` `min` setting (Grid has `max` only); the "Checks" table says the ten probes ship in `probes/`. **Adopt:** nothing to change.
- **Added (IP37, IP38):** `npx design-library-check`, the Never rules checked in your own project (bin `design-library-check`, `tools/check-project.mjs`). Errors are rules the guide already stated (styles in views, native `<select>`, selecting a core `data-dl`, descendant part paths, raw scroll regions, blur outside the material, literal or `all` transitions); warnings point at a missing seam (core tokens off the settings list, `!important`, primitive reads, raw sizes, a scaled root size, global selectors, raw interactive markup in parts, words in code). **Nothing fails the run during the Beta** unless you pass `--strict` or `--strict=all`; `--share` prints library and custom elements per view, `--json` the lot. **Adopt:** run `npx design-library-check --share` and work down its list at your own pace; add `--strict` to your build only when it's clean.
- **Changed (templates, no visual change):** the conference template's SponsorWall, Countdown and SponsorsLayout reach their parts by child paths, as the guide asks. A template copied from it keeps working; copy the new selectors if you want the check clean.
- **Added (IP19):** `Hero` `media` (any media in the picture's place, same arrangement: a MediaPlayer, a Carousel, your own arrangement of pictures), `trail` (what follows the opening inside it: key facts, partner marks, a cue; new token `c.hero.trail-gap`) and `fit` (`'content'` default, `'screen'`: fills the first screen less the sticky header, the opening centred). Without them nothing changes. **Adopt:** DesignUp's custom opening that redraws `Hero` becomes core `Hero` with `media={…}` for its collage or film, `trail` for what sits under it, and `fit="screen"` in place of scaling the root font size to fit the first screen.

## 0.2.0-beta.1 (2026-11-09): Beta, for early trials

The first **Beta**: ready for early trials in separate projects (React 19 with Vite 8). Every UX framework now comes in two parts, a guideline to design with and an objective checklist with a browser probe to judge with, and the library passed them on every template layout.

### Breaking

- **Token removed:** `--c-description-list-stacked-gap`. DescriptionList now draws its two columns once and its rows share them (`subgrid`), the term column as wide as its longest term; a narrow container stacks with the role gaps. Remove any override of the old token.
- **StackedBar markup:** the bar is now a `bar` part inside the root, with a `legend` part under it (each part's name and share beside its colour; `legend={false}` only when the numbers are written beside the bar). CSS that reached the segments as `[data-dl='stacked-bar'] > span` reaches them as `[data-dl='stacked-bar'] > [data-dl-part='bar'] > span`.
- **Layouts' regions are ScrollAreas:** AppLayout, ChatLayout and EditorLayout regions, Dialog and Sheet bodies, Canvas, Board, Carousel thumbnails and AvatarGroup's list scroll inside `ScrollArea` (the library's overlay bar), not a raw `overflow: auto`. Custom CSS that styled those regions' scrollbars or padding needs to move to the content inside.

### Added

- **Frame** layout part and framing from the hierarchy (Q88–Q94): a frame is a unit outside and a root inside; standalone `hero` and `cta` blocks (`standalone: true`) are framed; the renderer passes `siblings`, `neighbours` and `region` to blocks.
- **Compact chrome** (Q97): `data-density="compact"` on a chrome region's root gives small text and the shape's small radius; a new shape option, Mild.
- **AppLayout `head`** slot; `ChatLayout` and `EditorLayout` mark their `main` landmark.
- **Blocks:** `people` items, `person` and `byline` take an optional `picture`, an asset id from the template's `assets.json`, drawn as the person's portrait (initials when there's none; `person`'s `portrait: true` still shows initials alone). A form block's fields take `answer` and `invalid` for its failed screen state, so the kept answers show and the fields at fault are marked. Both are additive: existing content stays valid.
- **Canvas:** `CanvasLook` takes an optional `image` (a picture's address, drawn over the fill) and `imageFit` (`cover`, `contain` or `tile`), so an editor can draw image fills.
- **Probes ship in the package:** `@design-library/core/probes/{name}-probe.js` (spacing, layout, context, noise, material, motion, scroll, clipping, ui-states, visual), browser scripts that score each framework's checklist rows on a running screen.
- **Guide:** step 8, review every screen with the adversarial loop (an evaluator who didn't build the screen runs the probes and the look rows; fix at the owner; repeat); "Your own pictures" in step 6; the package `AGENTS.md` names the loop and every probe.
- **Notifications:** each pill carries `data-dismiss` (`auto` or `manual`).
- **Frameworks, two parts each** (docs): spacing and framing, layout, density, visual noise, materials and elevation, motion, scrolling, clipping, UI states and visual representation, each with its probe, and [the adversarial loop](https://prabinpebam.github.io/design-library/docs/#adversarial-loop.md) that runs them.
- **Pictures:** the templates' pictures generated from one reference per template, portraits for their people, sponsor marks.

### Fixed

- Spacing and grouping on every template layout (inner gaps smaller than outer at every level); columns sized by their own content.
- Focus rings no longer cut by FloatingBar's scrolling row or EditorLayout's bar and panel heads; floating shadows kept in previews; ChatMessage file names wrap instead of truncating with no way to read them.
- ListItem's `busy` is locked (`aria-disabled`); Button and MenuButton pending spinners don't turn while hidden; ColourPicker's popup paints its own floating surface.
- SiteLayout's sticky header is matched by scroll padding; AppLayout's view stays the widest region.
- Found by the full probe sweep at the release, at the window's full width and at 320 px: a section's EmptyState holds its parts closer than the section's own; a peek stage keeps one and a half page levels to the next band; AppLayout's view and details sit one and a half page levels apart (the gutter token is now the page level); a stacked Hero steps its gaps down once (`c.hero.stacked-*`) and its note sits a group under the actions (`c.hero.doing-gap`); Agenda's slots sit a section apart; DescriptionList breaks a long word (an address) instead of pushing the page sideways. New tokens are additive; the changed values are spacing only.
- Found by the separate-project proof's evaluator: a peek stage counts the band gap under it, so the next band still shows with the loose space preset (FR2, FR17); the noise probe treats an expanded toggle (ria-expanded="true") as a state, like a selected one (VN1); the Harbour template's header has no mark (the list icon read as a second menu, VR10) and its footer no longer repeats one link three times (VN10).

### Upgrading from 0.1.1

Install both 0.2.0-beta.1 tarballs together, apply the three breaking notes above (nothing else breaks: every other change is additive), then run your checks (`guide/1-install.md`, "Check it") and review each screen with the loop (`guide/8-review.md`).

## 0.1.1 (2026-11-09)

Fixes from the first separate-project install ([Handoff readiness](https://prabinpebam.github.io/design-library/docs/#handoff-readiness.md), F15.R6). Nothing breaks.

## 0.1.0 (2026-11-09)

First version handed to separate projects.

- **Core:** tokens (W3C DTCG) with light, dark and more-contrast contexts, generated CSS; 113 components across fundamentals, compounds and layouts (`agent/index.json`); content schemas and the renderer (`/render`); presets (`/presets`); fonts (`/fonts`, twelve self-hosted variable faces); icons (`/icons`); the colour generator (`/colour`); motion and materials; the agent guide (`AGENTS.md`, `guide/`).
- **Templates:** blog, chat, conference, corporate, design, harbour, portfolio and projects.
- **Supported:** React 19 in the browser, bundled by Vite 8 (see `guide/1-install.md`, "Supported").

### Upgrading

Install the new tarballs (or release URLs) for both packages together, read this file from your installed version up, and run your checks (`guide/1-install.md`, "Check it").
