# Changelog

Every release of `@design-library/core` and `@design-library/templates` (they share one version). Newest first.

**Versions:** `MAJOR.MINOR.PATCH`. While the major is `0`, a **minor** release may break a public contract (a prop, a block type, a token name, a content schema version, an export) and says how to upgrade under "Breaking"; a **patch** never breaks one. From `1.0.0`, only a major release breaks.

**Contracts that carry their own version:** the content schemas (`schemas/*.json`, `$id …/1`), the colour config (`colour-config/2`, `CONTRACT` in `@design-library/core/colour`), and each template's `content.schema.json`. A release that changes one names it here with the migration.

## Unreleased

- **Fixed (G14; core):** Dialog's Close button enables Button's new optional `minimumTarget` prop: at least the normal rem target and a token-driven 44 CSS px floor in both axes, including under root font reduction. Its small icon, keyboard behaviour and focus ring remain. Other Buttons retain their existing sizes unless opted in.

- **Fixed (G11; core):** a MenuButton's menu fits its widest item instead of always taking the full popup width (`c.popup.width`, 22rem), so two short actions no longer open a pane-wide menu. The existing maximum (`c.popup.width`, narrowed to the window) still caps it, and a longer label wraps. Select's listbox and Mentions are unchanged. Reported by DesignUp's header settings menu.

- **Added (G60, Q128; core):** AlignmentPicker `flow` (`row` | `column`): the chosen point, and a hovered one, draw three alignment bars laid out along the flow and aligned to the point instead of a dot, previewing the arrangement; tokens `c.alignment-picker.bar` and `bar-gap`. The Design tool passes its frame's flow.
- **Added (Q128; core + templates):** SegmentedControl `fill` (the group spans its row, options share it equally). NumberField `choice` (a short word at the box's end, e.g. Hug, Fixed or Fill, that opens a menu of the alternatives; no pending room, no chevron at rest). New icons `layout-free`, `layout-stack`, `padding-horizontal`, `padding-vertical`, `resize-fit`, `opacity`. Fixed: pressing a frame's name on the Canvas no longer also clears the selection. The Design tool's Auto layout section follows Figma: head toggle, Flow (four equal options, wrap beside), Resizing W/H with their choice and resize-to-fit, Alignment beside Gap (common values, settings), Padding as two fields with an individual-padding toggle, Clip content; a shape's Layout is Dimensions only.
- **Changed (Q129; templates):** no Switch in the Design tool inspector: independent corners and individual padding are icon toggle buttons, Opacity and Corner radius number fields side by side, and the remaining on/off settings Checkboxes.
- **Changed (Q127; core):** a field's leading part (TextField's icon or colour swatch, Select's icon, NumberField's scrub glyph or icon) sits in a square cell as tall as the box's inside, centred, with no start padding before it, so the space above, before and below it is equal at every size and density. New token `c.field.swatch` (the swatch's side, `size.icon-md` by default) lets a theme set a smaller swatch. The TextField Sizes story shows a swatch at every size.
- **Added (F15.FR9, Q123, Q126; core + templates):** Canvas gains `fill` (a page colour the person chose, over `c.canvas.fill`) and `c.canvas.size-fill` (the size label's fill, the selection colour by default), so a theme can keep thin selection lines bright and fill the label with an AA-passing colour. The Design tool: filled blue under white text is `#0A7ACB` (4.51:1) with darker hover and pressed, thin lines keep `#0D99FF`; with nothing selected (Escape, an empty-canvas click) the inspector shows Page, Styles and Export, and Prototype shows its settings and two dismissible help cards; sections follow the selection's kind (alignment inside Position, no Constraints by default, a frame's Auto layout, Selection colours before Layout guide, the Export button only with settings).
- **Changed (G52; core):** Switch's stories and docs no longer use visibility as their example; showing or hiding an item is VisibilityToggle.
- **Added (F15.FR1, Q118; core + templates):** a **template theme**. A template's `tokens/theme.json` re-decides core semantic roles and component tokens (never primitives) for its own screens only, under `[data-template="{id}"]`; a value is raw or `{ "light", "dark" }` (light-dark()). `npx design-library-template-tokens` writes `tokens/theme.css` and declares again, inside the scope, every core token that reads a re-decided one (and per density, space, shape and contrast context), so components follow with no fork. `TemplateView` sets `data-template` on each layout's root. EditorLayout gains `c.editor-layout.divider-width` (0 by default, unchanged look) and `c.editor-layout.divider` for a theme that draws a hairline between a docked panel and the working area. Canvas gains `c.canvas.handle-fill`, `selection-width`, `size-radius` and `name-selected` (defaults keep today's look). PropertySection gains `c.property-section.divider-width` (0 by default) and `divider` for a hairline between consecutive sections. SegmentedControl gains `emphasis="raised"` (the chosen segment a raised surface with accent text, `c.segmented-control.raised-*`) for a mode switch beside accent-filled tools, and `track={false}` where a surrounding bar already encloses the segments. A SegmentedControl option takes a `trailing` control (a design tool's flyout MenuButton): it sits inside the segment, never chooses it, reads on the chosen fill, and the radio keeps the option's own name. TreeView gains `actionsRoom="overlay"` (row actions take no room at rest and lie over the label's end on the row's surface, `c.tree-view.surface`, so labels use the full width), `mark="current"` (the chosen row is where you are: a neutral `c.tree-view.current-fill`), and a flat tree (no children) drops the twisty column. Tabs gain `c.tabs.selected-fill` (transparent by default) and `c.tabs.indicator-fill` (accent) for pill tabs; Button gains `c.button.expanded-fill` (the open disclosure's tint, `state.selected` by default). EditorLayout gains `toggles="inner"`: with panel heads, an open panel's toggle sits at the head's edge beside the working area, level with its first row. `template.schema.json` names `tokens/theme.json` under `theme`. Button gains `pressed` (Q121): a toggle button announced with `aria-pressed`, shown with `c.button.pressed-fill`; Switch stays the default for binary settings and a toggle button needs a `toggle-button:` reason comment above it. New icons `lock`, `unlock`, `pen`. EditorLayout gains `c.editor-layout.panel-start` and `panel-end` (both the panel width by default) so a theme can size one side (the Design tool's 330 px inspector, Q122). The UI type size is re-decidable per template through `text.xs`/`text.s`/`text.m` in its theme (the Design tool's 11 px, Q119/Q121.3). New compound **VisibilityToggle** (Q125): the eye and padlock toggles (`kind="visibility" | "lock"`, a pressed icon Button named "Show …"/"Lock …", the icon is the state so no fill, `c.visibility-toggle.pressed-fill`), the library's named pattern for showing, hiding or locking one thing in a list; it needs no written reason. The PropertyRow story's fill row uses it. The Design tool template is the first: Figma UI3's look (panels, canvas grey, 5 px controls, 13 px toolbar, the blue, 240 px panels, 48 px heads, 6 px white handles on a 1 px selection) in light and dark, with UI3's panel heads (main menu, file and project, File and Assets tabs; people, Present, Share) and the zoom on the inspector's tab row.
- **Changed (Q124, Q125; core):** `toggle-justification` also covers a standalone `Checkbox` (not inside a `CheckboxGroup`) used for a binary setting, and accepts the reason marker `binary-setting:` (as well as `toggle-button:`); visibility and lock toggles (`VisibilityToggle`, or a Button with an eye or padlock icon or a "Show/Hide/Lock/Unlock …" name) need no reason.
- **Added (Q121; core):** `design-library-check` error `toggle-justification`: a `Button` or `IconButton` with `pressed` (or `aria-pressed`) in a project's TSX needs a reason in a comment within the three lines above it, `{/* toggle-button: <why a Switch doesn't fit> */}`. A Switch stays the default for a binary setting; the rule text in the guide, Rules agents miss and the principles changes from "never a button toggle" to "Switch by default, a toggle button with a written reason".
- **Added (Q118.4; core):** `npm run check:generic` in the library repository: core code, CSS and tokens never carry a product's name in an identifier, selector or token, a product's brand value as a default, or a template's token namespace (comments may cite a product). `design-library-check` no longer warns on a generated template theme (`tokens/theme.css` with the generator's header), whose core-token re-declarations are the seam working; `design-library-template-tokens` validates its `theme.json`.
- **Changed (Q117; templates):** dark pictures are never made by colour correction, tinting, a filter or an inversion of the light file. Harbour's `shopfront-dark.webp` (a blue-tinted copy of the dusk picture) is replaced by the same scene regenerated at night (moon and stars, lamps and windows lit), and its shared alt says "in the evening" so it fits both files. A dark file is either supplied or regenerated with an image model, as **dark lighting** (the scene at night) or **dark canvas** (the drawing redrawn on a dark canvas); the guide, Rules agents miss and the Pictures page say so. The library's seedling story art (a recoloured SVG trio) is now an AI-drawn light-canvas, dark-canvas and more-contrast WebP set.

## 0.5.0-beta.1 (2026-11-10): brand pictures and openings

The pieces a brand-led site draws by hand around its pictures and openings, now in the library: an opening that keeps one height across a series, section titles at the opening's size, brand shapes over and under a picture, a second picture on hover or focus with the site's own reveal (the library keeps the triggers, the timing and reduced motion), the library's stipple as a public helper, glides timed by their distance, and `Illustration` for drawn art that follows the scheme, fits its space and moves only on the motion tokens. Every change is an addition: with nothing set, every opening, picture, title and glide is as before. A site on 0.2.0-beta.1 or later installs it with no edits. Upgrading: `UPGRADE.md`, section → 0.5.0-beta.1.

- **Docs and checks (MP23 and the 0.5.0-beta.1 rows; 0.5.0-beta.1):** guide step 6 "Illustrations" (drawing for the role classes, size groups and motion parts, naming, use from code and data, checks); the brand-led recipe's step 1 rows for `Hero` `reserve`, `Image` `decoration`/`under`, `alternate`, `reveal` with `@design-library/core/effects`, `Section` `size`, glide `pace` and `Illustration`; Rules agents miss rows for picture layers and illustrations; guide 6 links the library's Pictures page (Q115). - **Docs (Q115):** library page "Pictures" (`#/pictures`, after Image): every version of one picture, colour, greyscale, duotone or grey until pointed at, each with a light, dark or more-contrast file; what each is for, when it shows, how to set it in code and in `assets.json`, and what `design-library-check-content` and `design-library-check-svg` fail; live stories (`picturesStories` from `@design-library/core/stories`). ## 0.4.0-beta.2 (2026-11-10): moving a site onto 0.4

The small pieces a site needs to move onto the library completely: the router keeps the place between sibling pages (in code and from data), a template's parts can be used on their own, a theme can set the top type steps, a picture can have light, dark and more-contrast files, and a brand can use its own icons. Every change is an addition: with nothing set, every page, picture, icon and type step is as before, and the new checks only warn. A site on 0.2.0-beta.1 or later installs it with no edits. Upgrading: `UPGRADE.md`, section → 0.4.0-beta.2.

- **Docs (MP3, MP19, MP26; 0.4.0-beta.2):** guide step 3 "Your own icons" (name, convert, use, the resolution order, checks); guide step 6 "Pictures in every scheme" and "Use a part from another template"; the brand-led recipe's "Moving an existing site"; Rules agents miss rows for pictures per scheme, brand icons and page changes. `design-library-icons` and `design-library-check`'s `icon-name` accept `star` (Rating's mark). The new-template command's next steps show a picture entry with a `dark` file.

- **Added (MP1; 0.4.0-beta.2):** `Router` keeps the place between sibling pages. New props: `scroll` (`'top'`, the default and today's behaviour, or `'keep'`, or `(to, from) => 'top' | 'keep'`): kept in place, a new page doesn't scroll, focus stays on the link used and the new page's heading is still announced, and an anchor always wins; `again` (`'none'`, the default and today's behaviour, or `'top'`): a link to the page already shown glides back to the top on the motion tokens without a new history entry; `focus` also takes `(to, from) => selector | false`. New type `PageScroll`. Routing page story: an archive by year whose year links keep the place. **Adopt:** optional. A site that keeps its own place between sibling routes (a hand router, or a year in the query as a stopgap) passes `scroll={(to, from) => sameSet(to, from) ? 'keep' : 'top'}` and `again="top"`, and drops the hand code.
- **Added (MP2; 0.4.0-beta.2):** keeping the place from data. A page document with `collection` takes `"between": "keep"` (`page.schema.json`; default `"top"`): moving from one of its items to another keeps the place, as `Router` `scroll="keep"`. `site.json` takes `"again": "top"` (`site.schema.json`; default `"none"`): a link to the page already shown glides back to the top. `SiteView` passes both to the `Router` it makes (a site with its own enclosing `Router` sets `scroll` and `again` there); `PageDocument.between` and `SiteDocument.again` are typed. Harbour Books' reading page and site use both; Routing page story "Keeping the place, from site data". **Adopt:** optional. On a year or item page, add `"between": "keep"` and drop any query-string stopgap that kept the place.
- **Added (MP4; 0.4.0-beta.2):** a template's parts on their own. `@design-library/templates/{id}/registry` (new export path, for every template with a registry: conference, chat, design, projects) brings the template's registry, its parts and its token CSS, and none of its content files or pictures. The conference registry also exports `Countdown`, `SponsorWall`, `SponsorsLayout` and their prop types (`Sponsor`, `SponsorLevel`); the chat, design and projects registries export their apps. Measured with Vite (2026-11-10): a page placing the conference `Countdown` is 305 KB of script and styles through this path, against 442 KB through the template's full entry, which also brings its 23 pictures. Each template's Own parts page gains "Use these parts in another site"; the conference one shows a product-launch page using its `Countdown`. Existing paths are unchanged. **Adopt:** optional. A site that copied a template's part (a countdown, a sponsor wall) imports it from the registry path instead.
- **Added (MP15; 0.4.0-beta.2):** the top type steps as theme settings. `tokens/settings.json` gains a `Heading` entry: `--type-display-size`, `--type-display-weight`, `--type-display-leading`, `--type-display-tracking` and the same four for `--type-jumbo-*`, so `applySettings` and `settingsCss` accept them (and `themeSettings` lists them); `settingsErrors` refuses a jumbo size smaller than the display size when both are plain lengths. Statistic's large figure now reads `--type-display-weight` as well as the display size, leading and tracking (both default to bold, so nothing changes until a site sets it). Typography page: "A display face with one weight", the defaults beside a one-weight face at 4.6rem and 400 for display and 6.14rem for jumbo. **Adopt:** optional. A site that set `--type-display-size` on the root by hand (or sized its titles with its own tokens) calls `applySettings` with these names; for a display face with one weight, set both weights to `400` so nothing is faked bold.
- **Docs (MP3; 0.4.0-beta.2):** Hero page story "Breadcrumbs before the opening": core `Breadcrumbs` as the part before a `Hero`, at the layout's band gap, passing the spacing probe at 320, 1000 and 1440 px; with `opening="flush"` the trail would touch the header, so keep the spaced opening when a trail leads. - **Added (MP17; 0.4.0-beta.2):** light and dark pictures. `Image` takes `dark` (the same picture for a dark scheme) and `contrast: { light?, dark? }` (files for more contrast), each an address or `{ src, srcSet? }`; `src` stays the light or only file.
