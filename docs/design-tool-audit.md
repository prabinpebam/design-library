# Design tool audit

> **TL;DR:** The Design tool template (site.html#/app/design/editor) was compared with current Figma Design (UI3), from Figma's own help pages. The biggest gaps were in the layout: the tools sat in the header instead of floating over the canvas, the panels used the browser's scrollbar and scrolled sideways, and the inspector stacked every field at full width, with large headings. **F15.D1 fixed these in core**: EditorLayout has a floating tools slot and ScrollArea panels; PropertyRow is a new compound for two-column rows; Tabs, Select, Heading, PropertySection and Cluster gained compact options; and a selector that leaked into Tabs panels was fixed. The remaining gaps (inline field labels everywhere, layer row density, panel headers, the visibility control in a list row, auto-layout and stroke widgets) are listed below with a severity, the fix, and whether it belongs in core or the template. Nothing here is approved.

**Owner, 2026-11-08 23:01 (verbatim, [DoD Q68](definition-of-done.md#owner-instructions)):** *"Design tool - Toolbar should be floating - Scrollbar implementation is wrong and not as per design library - Horizontal scrollbar where it should not be - The layout and grid system for the various elements in the inspector panel is nothing like Figma. - Do a thorough audit and compare it with how Figma does it, maybe consider using smaller variant of input filed here. - This is a testr of the versatility of the Design library. - Do a thorough crit and audit of the gaps in the UI design and the layout compared to how it's done in actual Figma and fix everyuthing."*

**Status:** F15.D1 (audit plus first fixes) delivered for review on 2026-11-08 (strict design; only the build, type check, token generation and static checks were run, and nothing is approved). Shaped by `design-system`, `spacing`, `visual-noise`, `ui-states` and `ui-copy`. Stable IDs: findings **DT1–DT33**.

## Sources

Figma Design as of November 2026, from Figma's help centre:

- [Design, prototype, and explore layer properties in the right sidebar](https://help.figma.com/hc/en-us/articles/360039832014): "a file has three main interface elements that are detached from the canvas: the navigation panel on the left side of the screen, the toolbar at the bottom of the screen, the properties panel on the right side of the screen". The Design tab lists, in order: alignment, rotation and position; frame size; corner radius; constraints; layout guides; component properties; instance; auto layout; blend modes; text; fill; stroke; effects; export. A **Property labels** option adds visible labels; by default fields carry only an inline glyph or icon.
- [Explore design files](https://help.figma.com/hc/en-us/articles/15297425105303): five regions (navigation bar, left sidebar, canvas, right sidebar, toolbar). The right sidebar also holds Share, who is in the file, and the zoom and view options; there is no full-width header bar.
- [FD4B: Navigate Figma Design files](https://help.figma.com/hc/en-us/articles/30925881896727): the left sidebar holds the main menu, the file's name and the File and Assets tabs, with Pages above Layers.
- [Access design tools from the toolbar](https://help.figma.com/hc/en-us/articles/360041064174): Move (with Hand and Scale), region tools (Frame, Section, Slice), shapes, Pen and Pencil, Text, Comment, the Actions menu, and the mode switcher (Design, Dev Mode, Draw).
- [Adjust alignment, rotation, position, and dimensions](https://help.figma.com/hc/en-us/articles/360039956914): alignment sits at the top of the Design panel: align left, horizontal centres, right, top, vertical centres and bottom, with distribution next to them.

Density in UI3 (an 11 px interface type, 24 px fields in a 240 px panel, rows about 32 px apart, section titles at the text size in a heavier weight) is read from the product itself, not from a help page, and is used as a reference rather than copied. Where the library differs on purpose (its text is 14 px, not 11 px, so it stays readable and passes the text-spacing checks), the difference is stated.

## Findings

Severity: **S1** broken (clipped, overlapping, sideways scroll, an accessibility failure), **S2** misgrouped or nothing like the reference, **S3** fragile, **S4** polish. **Where** says whether the fix belongs in core (generic, every product gets it) or in the Design template. **D1** marks what F15.D1 fixed.

## Measured after F15.D1

- **Sideways overflow:** the properties panel's scroll region measured 0 px wider than the panel on the Design, Prototype and Dev mode tabs for a rectangle, a text layer and a frame (683 px window, panel floating). Before: 8 to 48 px.
- **Tabs:** fit in 240 px once `c.tabs.gap-sm` is applied (4 px left over before it).
- **Toolbar:** 40 px floating bar centred at the canvas's bottom, 16 px above its edge.
- **Still scrolls sideways on purpose:** nothing since D11 (the Dev mode CSS wraps, DT28).

F15.D4 measured the docked layout at 1280 px (both panels 256 px, 0 px sideways, no truncated labels, tools centred), 200 % text (panels 512 px floating, 0 px sideways) and 320 px (0 px sideways in both panels after DT32; the properties head overflows, DT33). Not measured: WCAG text spacing, dark and more-contrast contexts.

## Where it stands (F15.D13)

Every finding DT1–DT33 is fixed or matches, except where the owner's rules differ from Figma on purpose: binary settings (a layer's or paint's visibility, lock, individual corners, Property labels) are Switches, not icon toggles, and the text stays 14 px.
