# Templates and the library: what goes where

**Status:** audit and rule for review ([DoD Q139](definition-of-done.md#owner-instructions)), from building the IKEA-style store template (Q137, Q138). The improvements below are built in the `feat/brand-map` worktree (`..\dl-brand-map`, library on `http://127.0.0.1:8768/`), not yet merged. Rapid iteration, strict design: no tests.

> **TL;DR for agents:**
>
> - **A pattern goes in the core; a brand goes in the template.** If a second, unrelated kind of site would need it, and its behaviour, accessibility or formatting is more than layout, it's a core component. The template only supplies values (theme and part tokens), content (JSON) and compositions that only this brand makes.
> - **Meaning roles are never re-themed to mean something else.** `color.status.*` is for status. A template can't set it; a sale or a "New" tag reads `color.promo.*`.
> - **Rule of two:** when a second template needs a template part, promote it to the core with its look as tokens.
> - **Templates never rebuild mechanics:** scroll regions, number and currency formatting, focus, announcements and visually hidden text come from the core.

## The rule: library or template

Ask these in order. The first "no" sends it to the template.

1. **Would a second, unrelated kind of site use it?** Name one. A price is used by a shop, an events site selling tickets and a pricing page; a rail by a shop, a streaming catalogue and a news site. A product tile with a name in bold capitals is used by IKEA.
2. **Is there more to it than layout?** Behaviour, keyboard, focus, announcements, formatting (numbers, currency, dates), state, a scroll region. If it's only an arrangement of core parts, the template composes it.
3. **Can every brand's look be expressed as token values?** The IKEA price (a small raised sign, a yellow box with a red offset) is `c.price.*` values, so Price is core. If a brand needs a different structure, not different values, it's a template part.

Then it lives in these places:

| Layer | Lives in | Holds | Never holds |
| --- | --- | --- | --- |
| Roles | core tokens (`color.*`, `space.*`, `text.*`) | What each colour and size **means**: accent, status, promo, surfaces | A brand's values (those come from config or the template theme) |
| Patterns | core fundamentals, compounds, layouts | Structure, behaviour, accessibility, formatting, states | A brand's name, copy or signature |
| Knobs | core settings tokens (`c.<component>.*`) | Each pattern's look: radius, weight, sizes, which role it reads | Literal colours |
| Brand values | template `tokens/theme.json` | The brand's colours, fonts and shape, as values of core roles and knobs | Meaning changes: it may not set `color.status.*` |
| Brand compositions | template `parts/` (with `t.<template>.*` part tokens that alias core roles) | What only this brand arranges: its tile, its strip, its header until the core has slots | Mechanics the core owns (scroll, formatting, focus, hidden text) |
| Content | template `content/*.json` and `assets.json` | Words, products, pictures, alt text | Styles or paths in components |

**Rule of two and core fixes.** Generic gaps in core mechanics, slots or tokens found while building the library's own templates are fixed in core right away (defaults unchanged, regression sweep clean); outside consumers use a scoped temporary override plus a Library request until core ships; and a custom part in `parts/` promotes to core only when a second template needs it, with its look as `c.*` tokens and the old parts deleted. The full cycle, log format and triage rules live in [Template pressure-test loop](pressure-test-loop.md). Write `Not for` lines that name the core component a part would duplicate, as the IKEA parts do.

## Checks that keep the boundary

- `npm run tokens` fails when a template's `theme.json` sets a `color.status.*` role (R1).
- Template part tokens must alias core semantic roles, or be a measured `dimension` citing its reference (`template-tokens` check); a core token a part needs at its own value goes in `theme.json` `$parts`, never part CSS (`check:project` `core-token`, an error in template parts since C1).
- `check:clipping` knows the core visually hidden mechanism (R7), so a new allow-list entry for hidden text is a sign a part rebuilt it.
- Each template part says `Not for` and names the core component it would otherwise duplicate; reviewing a template is checking those lines against the core inventory.
